## 🔄 加载策略

### 阶段1：项目启动
**加载文档**: 
- [feature-prd.md](./feature-prd.md) ✅
- [task-list.md](./task-list.md) ✅
- [implementation-prd.md](./implementation-prd.md) ✅

**目的**: 了解整体功能和架构
**上下文大小**: ~3个文档

### 阶段2：任务执行
**按任务加载相关文档**，例如：
- **执行TASK-002时**: 加载 [TASK-002](./TASK-002-实现医生排班管理界面-prd.md) + [TASK-001](./TASK-001-设计预约数据模型-prd.md)
- **执行TASK-003时**: 加载 [TASK-003](./TASK-003-实现患者预约界面-prd.md) + [TASK-001](./TASK-001-设计预约数据模型-prd.md) + [TASK-002](./TASK-002-实现医生排班管理界面-prd.md)

**目的**: 专注当前任务，减少不必要信息
**上下文大小**: 2-3个文档

### 阶段3：集成测试
**加载文档**: 所有任务PRD + 实现设计文档
**目的**: 全面验证功能完整性
**上下文大小**: 8-10个文档

## 🛡️ 安全合规上下文自动包含

每个任务PRD文档自动包含以下安全合规内容：
- **认证授权要求** - 基于角色的访问控制
- **数据验证规则** - 输入验证和业务规则
- **隐私保护** - 患者数据保护要求
- **审计日志** - 操作记录和追踪
- **数据加密** - 敏感信息加密要求

无需额外加载安全合规文档，相关内容已内嵌在任务PRD中。

## 🔗 可追踪性保证

### 文档间引用
- **向下引用**: 父文档引用子任务
- **向上引用**: 子任务引用父文档
- **横向引用**: 任务间依赖关系

### 变更追踪
- 所有文档包含版本信息
- 依赖关系明确标注
- 变更影响分析自动完成

## 📊 上下文管理建议

### 开发阶段
```
启动项目：加载顶层文档（3个）
↓
任务开发：按需加载相关文档（2-3个）
↓
集成测试：加载所有任务文档（8-10个）
```

### 审查阶段
```
代码审查：加载当前任务+依赖任务
架构审查：加载所有相关设计文档
安全审查：加载安全合规相关文档
```
